## 3. Supabase — database (free)

1. Go to https://supabase.com → **New project**.
2. Fill in:
   - **Project name:** `flowcase`
   - **Database password:** make a strong one → **save it somewhere safe**
   - **Region:** `South Asia (Mumbai)` or `Southeast Asia (Singapore)` (closest to India)

4. Open **Project Settings → Data API** (older dashboard: **Connect**):
   - Find **Connection string → Transaction pooler** (port `6543`)
   - Copy the URI. This is your **DATABASE_URL**.
   - (It also already exists in your local `.env` as `DATABASE_URL` — same thing, you can just copy from there.)
5. Open **Project Settings → API** (older: **Connect → App Frameworks**):
   - Copy **Project URL** → this is `SUPABASE_URL`
   - Copy **anon / public** key → this is `SUPABASE_ANON_KEY`
   - Copy **service_role** key → this is `SUPABASE_SERVICE_ROLE_KEY` (keep it secret!)
6. Now fix the Auth settings (very important):
   1. Left menu → **Authentication → Sign In / Providers → Email**
   2. **Confirm email** → keep it **ON** (this is how you set it up). New
      customers sign up → get a confirmation email → the link drops them
      straight into their account. Turn it OFF only if you want instant
      signup with no email.
      ⚠️ Free Supabase sends only a few auth emails per hour — if signups say
      “email rate limit exceeded”, wait a while (or turn this OFF).
   3. **Providers → Google** must show **Enabled** (you already turned it on).
      Customers click **Continue with Google** → Google → back to their account.
   4. **Providers → Phone** must show **Enabled** with **Twilio** as the SMS
      provider (you already set this up) — it powers the one-time SMS step.
   5. Left menu → **Authentication → URL Configuration**:
      - **Site URL:** `https://flowcase.in`
      - **Redirect URLs:** add both:
        - `https://flowcase.in/account/auth/callback`
        - `http://localhost:3000/account/auth/callback`

## 8. Render — backend + Medusa admin panel (free)

2. **New + → Web Service** → select the `Flowcase_web` repo → **Connect**.
3. Fill in:

   |---|---|

   ⚠️ The **Build Command** must be typed exactly, with **no quotes, no backticks, no line break**:

   ```
   npm install && npm run build
   ```

   If a stray quote/backtick slips in, Render's log dies immediately with
   `bash: -c: line 1: unexpected EOF while looking for matching` — retype the
   field clean and Save.

   The same rule applies to the **Start Command**: type plain `npm start`, no
   backticks. If Render's log shows `` Running '`npm start`' `` followed by
   `bash: line 1: >: command not found` / `Exited with status 127`, the
   backticks made bash execute the log output as a command — retype it clean.

### 8.5 First-time database setup + admin login + product seed (3 one-time commands)

Your database is brand new and empty. Fill it (only once):

> **No Shell tab (Render free plan doesn't include it)?** Run the same 4 commands from **your own computer** — they hit the exact same database:
> 1. In `E-com/apps/backend`, rename `.env.local` → `.env.local.bak` (it would override the production database URL).

   npx medusa exec ./src/scripts/seed-flowcase.ts

   npx medusa exec ./src/scripts/seed-accessories.ts

   *(adds the 50 speakers / power banks / cables / MagSafe / AirPods accessories — idempotent, safe to re-run)*

3. ⚠️ **While the seed runs, look at its log output.** Near the end it prints:

   ```
   Publishable key: pk_............
   ```

   **Copy that key** — you need it in Step 9 (Vercel).
   (It is *different* from your local one, because it is a fresh database.)

4. Type `exit` to close the shell.

## 12. UptimeRobot + keepalive (stop the free services from sleeping)

Free services sleep/pause when nobody touches them. Two small fixes:

### 12.1 UptimeRobot (keeps Render awake + tells you if the site breaks)

1. https://uptimerobot.com → sign up → **Add New Monitor** (do it twice):

   | # | Type | URL / Interval |
   |---|---|---|

3. Both monitors must turn **green** after the first check (1–2 min).
   Monitor 1 also stops Render from sleeping (it pings every 5 min — Render sleeps after 15 min of silence).

### 12.2 GitHub Actions keepalive (stops Supabase from pausing after 7 idle days)

1. GitHub → `Flowcase_web` repo → **Settings → Secrets and variables → Actions → New repository secret**, add all three:

   | Secret name | Value |
   |---|---|
   | `SUPABASE_DB_URL` | your Supabase pooler URL (= `DATABASE_URL` from .env) |
   | `MEDUSA_URL` | `https://flowcase-backend.onrender.com` |
   | `STORE_URL` | `https://flowcase.in` |

2. **Actions** tab → click **keepalive** on the left → **Run workflow** → **Run workflow**.
3. Open the run → the “Ping Supabase…” step must show **PASS / OK**. ✅
4. Done — it now runs by itself every 3 days at 09:30 IST.

> Supabase free pauses your database after 7 days with zero activity. This one query (`SELECT 1`)
> every 3 days keeps it alive. UptimeRobot **cannot** do this (it only does HTTP).

## Troubleshooting (the usual suspects)

| Problem | Fix |
|---|---|
| Render build fails: `bash: -c: line 1: unexpected EOF while looking for matching` | The Build Command field has a stray quote/backtick → retype it exactly `npm install && npm run build` (plain text, no quotes, no backticks) → Save (redeploys) |
| Render deploy: `Error: connect ECONNREFUSED ::1:5433` | `DATABASE_URL` was copied from `.env.local` (local dev) → replace it in Render → Environment with the Supabase pooler URL from `.env` (port `6543`) → Save. Scan all env vars: none may contain `localhost` |
| Render deploy: `bash: line 1: >: command not found` + `Exited with status 127` | Start Command has backticks around it → retype it exactly `npm start` (plain) → Save |
| Render deploy: `relation "currency" does not exist` / `relation "payment_provider" does not exist` | The database is connected but **empty** — tables were never created. Run the 3 one-time commands in Step 8.5 (Shell tab — or from your own computer if you are on the free plan, see the note in 8.5), `npx medusa db:migrate` first, then let the service restart |
| Render build fails: “JavaScript heap out of memory” | Render → Environment → add `NODE_OPTIONS` = `--max-old-space-size=450` → Save (redeploys) |
| Storefront shows **no products** | Seed did not run — redo Step 8.5. Check admin → Products. |
| Browser console: **CORS error** (`blocked by CORS policy`) | Fix the three CORS values exactly (Step 8.2) → Save → wait for redeploy → hard-refresh |
| Admin login **wrong email/password** | Run in Render Shell: `npx medusa user -e admin@flowcase.dev -p "YOUR_ADMIN_PASSWORD"` |
| Admin shows **401** in console when logged out | Normal — the API protects itself. Log in and it stops. |
| Site opens **very slow** once | Render free instance was sleeping → first load warms it. UptimeRobot (12.1) stops this. |
| Supabase **paused** (dashboard says project paused) | Supabase → un-pause, and run the GitHub **keepalive** workflow once; it never pauses again |
| Changed a `NEXT_PUBLIC_…` value but nothing changed | It is baked into the build → Vercel → Deployments → ⋯ → **Redeploy** |
| Razorpay webhook error / 404 | URL must be exactly `https://flowcase-backend.onrender.com/razorpay-webhook`; secret must equal `RAZORPAY_WEBHOOK_SECRET` |
| Domain doesn’t open after hours | Re-check the 3 DNS records (Step 10.3): name `@` / `www` / `admin`, no duplicate old records; wait for propagation |
| New products uploaded from admin don’t show | Admin → products → click **Publish** (drafts are not visible on the store) |
| Storefront build shows **0 routes / empty manifest** | Cancel → **Redeploy** (a corrupted cache build) |
| Signups say **“email rate limit exceeded”** | Free Supabase allows only a few auth emails per hour → wait an hour, or turn **Confirm email** OFF for instant signup |
| Customer stuck on **“Verify phone”** | They must finish the one-time SMS step — if no SMS arrives, check Supabase → Authentication → Providers → Phone (Twilio) is enabled |
